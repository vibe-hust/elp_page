01 · Multimodal Overview

Find better loops for image, text, and video models

Repeating transformer blocks can improve a pretrained model without changing its weights. ELP uses an AI agent to find useful loops: which blocks to repeat, how to update their hidden states, and when to reuse earlier work.

The agent also adjusts sampling schedules and guidance. After search, selected programs run as fixed code and settings, with no further search-agent calls. We test them on 9 frozen backbones for image generation, text reasoning, and video generation.

01

Search over code

The search can change both the update code and its settings, instead of choosing only from a fixed menu.

02

Inspect each run

The agent writes checks to see how features, guidance, and updates change during generation. It uses these observations to propose edits.

03

Test across 9 models

The same framework is tested on 9 image, reasoning, and video models. Their weights stay fixed.

Multi-domain Pareto improvements with frozen weights. Interactive vector plots across Scale-RAE, Looped-DiT-B32 (panels a–c) and RememBench video world models (panel d).

Executable program editing expands the retained Pareto frontier. On Scale-RAE under an 80-candidate budget (R0–R8), full loop program search reaches a cumulative hypervolume of 0.9148 vs. 0.7923 for configuration-only search.

Feedback-guided search vs. grid enumeration. Coordinating structure, state dynamics, and outer execution control avoids exponential grid sweeps.

02 · Methodology

How the search works

Search runs offline for each model. The selected programs then run without further calls to the search agent or changes to model weights.

Choose Scale-RAE, Looped-DiT-B32, LongLive 2.0, or Dory1.0-4B to follow the code changes, observations, and results.

ELP tests each program and records what happened. The agent uses those results to improve the next round of programs.

1. Write a loop program

Structure · Dynamics · Control

Each candidate p = (c, λ) contains code c and settings λ. Together, they decide which blocks repeat, how states change, and when earlier work is reused.

st(k+1) = Uθ,p(st(k); t, k) Eq. (2)

2. Inspect the run

Runtime Traces

The agent writes checks Dr for development inputs. These inspect how features, guidance, and updates change between repetitions and sampling steps.

𝓞r(p) = Dr( Traceθ(p, 𝓧dev) ) Eq. (3)

3. Improve the program

Offline Refinement

At round r, the agent uses earlier results, failures, and observations to propose new programs. The target a tells it which outcomes to prioritize.

𝓟r+1 = LLM(𝓒r, 𝓗r, 𝓞≤r; a) Eq. (4)

4. Choose a speed–quality trade-off

Frozen Deployment

Keep programs that offer useful trade-offs between quality and speed. Select fixed Speed, Balanced, and Quality programs for use after search.

v(p) = (q1(p), …, qm(p), T(p0)/T(p)) Eq. (5)
